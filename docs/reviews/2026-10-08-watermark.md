# GIF 目录入口与文本水印

## 行为

- 空闲菜单在「设置…」之前增加「打开 GIF 存储目录」，点击时读取当前输出目录；失效目录提示重新选择。设置里的「在访达中显示」共用这条逻辑。
- 新增水印开关和文字输入，默认关闭，最多 40 个字符，按 Swift Character 截取，不拆开组合 emoji；换行和连续空白转成单个空格。
- 关闭保留文字，空白不绘制，录制开始时快照水印设置，避免中途修改影响本次导出。
- AppKit 绘制中文和系统彩色 emoji；整层 48% 不透明度，白色文字与轻微暗色阴影。名义最大字号 14 px，最长占画面宽度 35%、高度 20%，边距按成片尺寸缩小，最大 12 px。
- CLI 的私有 `--watermark-overlay` 参数只接收 app 已渲染的临时 PNG；用户界面只支持文本。临时素材在转换结束或无法启动进程时清理。
- 先完成关键帧检测、裁剪、缩放，再叠水印并生成调色板。保证右下角是最终成片的右下角，不让水印干扰运动分析。

## 验证

- `npm test`：16/16。新增真实 ffmpeg 逐帧检查，覆盖裁剪和缩放后的右下角位置、两种调色板模式、帧数与时长保持不变，以及窄小画面的布局。
- `npm run test:native`：12/12。覆盖新旧偏好、开关与文字持久化、空白输入、录制快照、组合 emoji 字符计数，以及中文和彩色 emoji 的实际像素与半透明度。
- 原生构建、签名验证、`git diff --check` 通过。
- 用 AppKit 生成的中文与 emoji 水印跑了应用内置 CLI，真实产出 GIF 并查看解码帧。示例在 `native/build/review/bundled-watermark.gif`。
- `screenshots/settings-watermark.png` 使用实际 `AppSettingsView` 离屏渲染，示例偏好采用内存存储，未修改用户偏好。它只展示滚动窗口顶部，不代表实机点击验收。
- 实机 UI 自动化两次报 `Sky Computer Use native pipe closed before response`，因此菜单点击、目录弹窗与真实输入交互仍未端到端验收。运行中的旧进程未被强制终止；退出并重开构建后的 app 才能加载新代码。

## pen.dev 优化建议

当前界面是 SwiftUI/AppKit 原生窗口。pen.dev 可用于布局、视觉和状态设计，完成后再按设计改 SwiftUI。官网列出的 HTML/CSS 导出不能直接替换这个窗口。

建议流程：在项目 `design/` 下新建独立 `.pen`，以当前设置截图和 `native/Sources/SettingsWindow.swift` 为参考；对比「单页分组」与「通用 / 导出 / 快捷键」分页方案；确认后再映射回原生控件。不要修改 pen.dev 当前打开的学习指南画布。

建议给设计任务的说明：

> 优化 screen2gif 的 macOS 原生设置窗口，中文界面、紧凑布局、系统字体和蓝色强调色。包含通用、导出、快捷键三个页签。通用放提示音；导出放输出目录、打开/更改目录、三档画质、导出后显示文件、文本水印开关/输入/右下角预览；快捷键保留录制全屏、框选、停止三项及冲突提示。设计水印关闭、开启有文字、开启空白、40 字符的状态，兼顾深浅模式和键盘操作。不要添加图片水印、位置或样式选择。

参考：[pen.dev 官网](https://www.pen.dev/)（MCP 画布设计与 HTML/CSS 导出能力）。本轮仅检查连接并提供流程，未创建或修改 `.pen` 文件。
